## Parent

Part of #1 — [Windows RAW 采集文件批量时频图浏览与 PNG 导出应用](https://github.com/JimYang816/TF_Decoder/issues/1)

## What to build

用户连续浏览约 100 个采集文件时，应用在后台预取相邻图，通过有容量上限的缓存减少切图等待。优先完成当前查看请求，参数变化、快速切换和缓存淘汰后仍显示正确结果，并用现有数据记录实际响应与内存表现。

## Acceptance criteria

- [ ] 导入后先服务当前文件，在后台预取相邻图；前台切图请求优先，不要求用户等整批分析完毕。
- [ ] 缓存有明确的内存容量约束，超出预算可淘汰结果；浏览文件列表不按文件数量累积所有完整时频矩阵。
- [ ] 文件身份和已应用计算参数相同的结果保持一致；配置变化、缓存命中／淘汰或预取完成顺序不导致错误文件、旧配置或错误色阶成为当前图。
- [ ] 仅调整视口与显示频率范围不重新定义计算结果；文件自身的浏览视口与计算缓存分开保持正确行为。
- [ ] 通过已有应用级入口验证预取、快速切图、配置变化与淘汰后的外部结果一致性；不依靠私有缓存结构或内部调用次数作为正确性判据。
- [ ] 使用约 100 个文件及现有约 64 MiB 的典型最大样本，测量首次显示、已缓存切图、缩放响应和峰值内存，记录硬件、配置、缓存预算与测量结果。
- [ ] 测量与实际操作证明界面持续可响应、内存受控；发现瓶颈时在本切片中优化到满足这些行为，不声称未经测量的具体耗时、C++ 速度比较或未来文件上限。
- [ ] 已有单文件、文件夹浏览及参数应用验收保持通过；若批量导出分支已合并，同时验证共享分析资源下的交互和结果正确性。
