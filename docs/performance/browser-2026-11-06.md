# 有界缓存与相邻预取实测（2026-11-06）

测试脚本：[scripts/measure_browser.py](../../scripts/measure_browser.py)；机器可读结果：[browser-2026-11-06.json](browser-2026-11-06.json)。实际数据仅读取，仓库只保存汇总指标，不复制 RAW 或来源文件名。

机器为 AMD Ryzen 5 7640HS，12 逻辑处理器，可用物理 RAM 总量 16,312,553,472 字节（15.19 GiB），Windows NT 10.0.26200。Python 3.13.9、PySide6/Qt 6.9.2、NumPy 2.5.4。Qt 使用 offscreen 平台，窗口 1200×780；图形实际绘制，缩放后用 `graphics.grab()` 强制完成绘制。此环境验证不代替真实显示器、高 DPI 和打包 EXE 验收。

参数为 96 kHz、1024 点原 hanning 窗、512 重叠、1024 FFT、滤波关闭、显示 0–48 kHz。导入原目录的 167 个 RAW（2 个空文件），随后浏览 100 个实际非空文件，包含最大 67,174,400 字节文件。没有复制、链接或改写源数据。100 是实际浏览工作量；导航列表保留全部 167 项。

| 项目 | 实测 |
| --- | --- |
| 最大 RAW 首次显示 | 0.882 秒 |
| 目录导入到首图 | 0.246 秒 |
| 100 文件浏览总耗时 | 63.834 秒 |
| 切图中位数 / 最大值 | 0.290 / 1.967 秒 |
| 相邻预取等待 2 秒后的切图 | 34.6 毫秒（含 GUI 绘制） |
| 20 次缩放并绘制中位数 / 最大值 | 16.6 / 30.7 毫秒 |
| 进程峰值 RSS / 稳定 RSS | 914.1 / 430.3 MiB |

最大 RAW 生成 513×32767 的双精度 PSD 与 dB 矩阵，连同时间、频率数组共 269,217,776 字节（256.75 MiB）。缓存默认预算 384 MiB，只能容纳一个这样的最大结果；相邻预取会淘汰较旧结果。缓存按全部四个数组的 `nbytes` 计费，浏览视口只保存范围而不保存矩阵。预算是缓存保留量，**不是进程 RSS 上限**：当前显示、正在计算、导出快照、FFT 工作区和 Qt 均独立占用内存，调用方保留 Future/结果也会延长数组寿命。大于预算的单个结果可显示，但不进入缓存。

计算把 FFT 工作区限制在每批 256 个窗；源字节和整数样本在电压换算后及时释放，dB 就地计算，避免全文件 FFT 中间矩阵同时驻留。100 文件期间每 10 项记录的 RSS 为约 421–651 MiB，没有按文件数持续累积所有完整矩阵。10 毫秒独立线程采样捕获上述峰值；RSS 还包含 Python/NumPy 内存分配器保留空间。

Qt 10 毫秒心跳在最大 RAW 首次显示期间触发 80 次，最大间隔 50.9 毫秒；100 文件工作量期间触发 5703 次，最大间隔 139.7 毫秒。界面事件循环持续运行；139.7 毫秒说明仍有短暂绘制或调度停顿，不承诺每帧 10 毫秒。前台使用一个分析工作线程，新提交的前台请求排在等待中的旧前台请求之前，所有前台请求排在预取之前；正在执行的读取/FFT 不强制中断。缓存命中同步提供已完成 Future，不等待正在进行的预取。

浏览后返回最初三项分别用时 0.275、1.470、0.238 秒；样本数、电压范围、全文件色阶和 PSD 两个端点与首次结果一致。行为测试通过唯一 `Application` 入口进一步比较完整 PSD、文件修改后的新结果、淘汰后的视口恢复、快速切换与新参数，以及在文件系统边界控制相邻预取时最新前台请求优先完成。测试不检查私有缓存结构或内部计算次数。

本次读取受到操作系统文件缓存、开发机其他进程和磁盘状态影响；没有清空系统页缓存，因此“首次显示”是该应用实例的首次分析，不是冷盘基准。不据此推断未来文件上限或与 C++ 的速度比较。

复现（在仓库根目录，另安装 psutil）：

```powershell
python scripts/measure_browser.py '本地采集目录' --output docs/performance/browser-local.json
```
